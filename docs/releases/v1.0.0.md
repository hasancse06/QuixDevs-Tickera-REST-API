# QuixDevs Tickera REST API v1.0.0

## Overview

Initial free, open-source release of the independent QuixDevs WordPress extension for standalone Tickera events and ticket types. Authenticated authors can create, list, retrieve and partially update only their authorized resources. This document prepares release notes; it does not announce an already published release.

## Main features

- Eight authenticated event and ticket-type management operations.
- Strict actual authorship plus WordPress capability checks, including parent-event ownership for tickets and no administrator ownership bypass.
- Explicit writable/readable fields, JSON validation, bounded pagination and private/no-store responses.
- Site-local event dates, location, terms, existing categories and owned images.
- Decimal-string ticket prices, finite/unlimited quantity, sale ranges and owned templates.
- Verified standalone Tickera metadata mappings and native save hooks.
- Nonblocking related-write locks, safe dependency handling and no Composer runtime requirement.

Purchasing, checkout, payment gateways/Stripe, refunds, orders, attendees, check-in, deletion and WooCommerce Bridge products are outside scope. WooCommerce is unnecessary.

## REST API endpoint summary

Base: `/wp-json/quixdevs-tickera/v1`. All eight operations require authentication and the relevant ownership/capability checks.

| Method | Endpoint | Purpose |
|---|---|---|
| GET | /events | List own editable events |
| POST | /events | Create an event as the authenticated user |
| GET | /events/{id} | Retrieve an owned event |
| PATCH | /events/{id} | Partially update an owned event |
| GET | /events/{id}/tickets | List authorized ticket types under an owned event |
| POST | /events/{id}/tickets | Create a ticket type under an owned event |
| GET | /tickets/{id} | Retrieve an owned ticket type with an authorized parent |
| PATCH | /tickets/{id} | Partially update an owned ticket type |

Reads and PATCH return 200; creation returns 201. See the [full contract](../rest-api.md) for fields, example responses and errors.

## Authentication and author ownership

Use per-user WordPress Application Passwords over HTTPS for external clients, or a logged-in WordPress cookie plus a valid wp_rest nonce in X-WP-Nonce. A nonce alone does not authenticate a user. Provision only the required Tickera creation/editing capabilities; the addon grants none automatically.

Actual event authorship must match the caller. Tickets require both ticket ownership and ownership/edit permission for the valid parent event. New authorship is forced to the authenticated creator. Forged owner fields, unsupported metadata and ticket reassignment are rejected. Anonymous access returns 401; foreign/nonexistent resources return generic 404; owned but uneditable objects return 403. These rules also apply to administrators using this API.

## Installation

1. Download **quixdevs-tickera-rest-api.zip** from the release's Assets after publication, along with its SHA-256 file.
2. Verify the adjacent checksum from the download directory with `shasum -a 256 -c quixdevs-tickera-rest-api.zip.sha256`.
3. Ensure standalone Tickera 3.6.0.8 is installed and active.
4. In WordPress Admin, choose Plugins > Add New > Upload Plugin, upload the lightweight ZIP, click Install Now and activate the addon.
5. Set the site timezone, provision the API author's capabilities and configure authentication.
6. Call GET /events as that user, then retrieve an owned event ID.

The canonical installation directory is `quixdevs-tickera-rest-api/`. Composer is unnecessary on the server. GitHub's automatic Source code ZIP contains the development repository and is not the recommended WordPress installer. No addon settings page or shared API key is required.

## Tickera requirements and tested environments

Requirements: WordPress 6.8+, PHP 8.1+, MySQL/MariaDB connection advisory locks and standalone **Tickera 3.6.0.8** (`tickera-event-ticketing-system`). Other Tickera versions fail closed with 503 until verified. Detected Bridge/custom relationship mode blocks ticket operations with 409; event operations remain available. Premium Bridge compatibility is not claimed.

Public [Quality CI](https://github.com/hasancse06/QuixDevs-Tickera-REST-API/actions/runs/38745788491) passed all eight PHP 8.1/8.2/8.3/8.4 × WordPress 6.8/7.1.3 jobs with MySQL 8.0 and pinned Tickera at commit cf3c6bf6624889e4372ec4ad0dc837ff9d881228. ## Security and operational notes

Input/output fields are allowlisted and content is sanitized. Responses do not expose arbitrary metadata or private Tickera API keys. Publication/private edits require appropriate capabilities. Related addon writes are serialized and return quixdevs_resource_busy/409 on contention or unavailable locks; retrieve current state before retrying.

Native admin/other-plugin writes do not share these locks. WordPress post/meta hooks are not transactional: late failures may partially persist, and blind POST retries can create duplicates. Honor private cache headers and render returned content safely. Strict ownership governs this addon's namespace; native Tickera/WordPress routes retain independent policies.
